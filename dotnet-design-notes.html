最近学习 C# 时，我读到了微软介绍 .NET 设计要点的文档。下面结合一些简单例子，记录我目前的理解。原文见 Introduction to .NET。

1. 开发效率来自整个技术栈的配合

.NET 将语言、运行时、类库和开发工具结合起来，帮助开发者完成从编写代码到调试、运行和部署的工作。

层次典型组成
编程语言C#、F#、Visual Basic
运行时负责代码执行、垃圾回收、即时编译等
基础类库集合、文件 IO、网络、并发等
开发工具Visual Studio、.NET CLI、调试器
应用框架ASP.NET Core、WPF、WinForms、.NET MAUI 等

例如，用 C# 编写串口调试程序时，可以使用 SerialPort。在现代 .NET 项目中，先添加 System.IO.Ports NuGet 包，再编写：

using System.IO.Ports;

// COM3 和波特率需要根据实际设备修改
using var port = new SerialPort("COM3", 115200);
port.Open();
port.WriteLine("Hello STM32!");

这样就不必自己封装底层串口 API，可以先关注发送什么数据、如何解析设备返回的信息。SerialPort 文档

当然，Qt 也提供了 QSerialPort。这里强调的是 .NET 各部分的配合，以及它们对开发工作的支持。

2. 默认使用安全代码，也允许按需使用 unsafe

日常 C# 开发通常使用托管代码，由运行时提供垃圾回收、数组边界检查等机制，减少直接管理内存时容易出现的问题。

如果需要使用指针，可以进入 unsafe 上下文。例如：

unsafe
{
    int value = 100;
    int* ptr = &value;

    *ptr = 200;
    Console.WriteLine(value); // 输出 200
}

编译这段代码，还需要在项目文件的 <PropertyGroup> 中启用：

<AllowUnsafeBlocks>true</AllowUnsafeBlocks>

这个例子展示了通过指针修改变量。unsafe 文档

3. 同时支持静态和动态能力

这一点涉及的范围比较广。可以先从 C# 的静态类型检查和 dynamic 理解其中一个方面。

C# 是静态类型语言。下面的变量声明为 int，因此不能直接给它赋字符串值：

int x = 10;
x = "Hello"; // 编译错误

如果使用 dynamic，下面的赋值可以正常执行：

dynamic x = 10;
x = "Hello";

Console.WriteLine(x.Length); // 输出 5

dynamic 会将部分操作的绑定和检查推迟到运行时。如果实际对象不支持某个操作，执行时仍然可能发生异常，因此不能简单理解为“使用 dynamic 就不会报错”。dynamic 文档

此外，.NET 还提供反射、运行时代码生成等能力，并支持 Native AOT 这样的提前编译部署方式。不同方式存在各自的限制，例如 Native AOT 不支持运行时代码生成，使用时需要检查兼容性。Native AOT 文档

4. 能够与原生代码协作，也提供访问 CPU 指令集的能力

这一点可以拆成两部分理解。

第一部分是原生代码互操作。C# 程序可以通过相应接口调用已有的本机库，从而使用操作系统功能或其他语言实现的组件。原生互操作文档

结合上位机开发，可以设想这样的场景：设备厂商提供了相机、采集卡或运动控制卡的原生 SDK，上位机通过厂商提供的 .NET 封装，或通过 P/Invoke 等方式调用 SDK，完成设备控制和数据读取。

第二部分是硬件内建指令。例如，.NET 提供了访问 CPU 向量运算能力的接口，可用于部分计算密集场景的底层优化。这里涉及的是处理器指令集，例如 SIMD 向量运算。硬件内建指令文档

5. 支持跨平台，也允许针对特定平台开发

现代 .NET 支持 Windows、Linux、macOS，以及 x64、ARM64 等处理器架构。不过，具体应用能否跨平台，还取决于使用的框架、类库和系统接口。

例如，ASP.NET Core 应用可以部署到不同操作系统；WPF 和 WinForms 则用于 Windows 桌面应用。微软也明确说明，WPF 虽然属于现代 .NET 的组成部分，但仍然只能在 Windows 上运行。WPF 文档

因此，选型时既要看 .NET 平台本身的能力，也要检查项目依赖的 UI 框架、设备驱动和厂商 SDK 是否支持目标平台。

6. 基础编程能力可以在不同应用领域复用

.NET 面向不同应用领域提供了不同的框架，而 C# 语法、集合、异常处理和异步编程等基础知识，可以在多个领域继续使用。

应用领域典型技术或组合
Windows 桌面软件WPF、WinForms
Web 后端ASP.NET Core
移动应用.NET MAUI
游戏开发Unity 使用 C#，但其运行时技术栈与现代 .NET 存在差异
工业上位机桌面框架、通信类库、设备 SDK

例如：

await Task.Delay(1000);

这表示异步等待一秒，等待期间不需要阻塞当前线程。

async / await 可以用于桌面程序中的异步操作，也可以用于 Web 服务的异步 IO。

学习一种应用框架时积累的基础能力，往往可以带到其他领域；同时，每个领域仍有自己的框架用法和业务知识需要学习。

7. 优先采用已有的行业标准和开放生态

.NET 的设计也强调与其他技术生态协作，例如支持 OpenTelemetry 和 gRPC。

OpenTelemetry 用于采集和传递日志、指标、调用链等观测数据，帮助开发者了解程序的运行情况。OpenTelemetry 文档

gRPC 用于服务之间的远程调用，也支持不同语言实现的服务相互通信。gRPC 文档

采用这些通用技术，有助于 .NET 应用接入现有系统，也让开发者可以根据项目需要选择不同的服务、工具和基础设施。
